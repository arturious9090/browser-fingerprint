# Диагностика проблем

[Оглавление](README.md)

## С чего начать

Локально смотрите вывод процесса Node. На VPS:

```sh
docker compose ps
docker compose logs --tail=50 app caddy
```

Сопоставляйте `X-Request-ID`/`requestId` ответа с журналом app. Не публикуйте ключ владельца, cookies, CSRF, JSON отчётов и полный дамп БД при разборе проблемы.

`GET /healthz` — liveness процесса. Даже при 200 запись может быть недоступна из-за квоты, заполненного диска или SQLite. Проверяйте конкретный сценарий и статус ответа.

## Запуск и доступ

| Симптом | Проверка и действие |
| --- | --- |
| Node не стартует, ошибка библиотеки `simdjson` | Ошибка установки Node до выполнения приложения. Используйте исправный Node 24.13+; локальная рабочая команда указана в руководстве разработчика |
| Порт занят | Используйте свободный dev-порт: `PORT=4174 npm start`. Не завершайте неизвестный процесс на занятом порту |
| После правки виден старый интерфейс | Node кеширует статические файлы при старте. Перезапустите dev-процесс либо пересоберите и пересоздайте Docker app |
| Production не стартует | Проверьте HTTPS `PUBLIC_ORIGIN`, абсолютный `PROXY_SOCKET`, loopback `ADMIN_ORIGIN` и права каталога БД |
| Изменение `.env` не действует локально | `npm start` не читает `.env` автоматически. Передайте окружение явно; Compose использует собственные подстановки |
| В контейнере `Permission denied` для БД/socket | App работает с UID 1000. Проверьте владельца data/socket volumes, каталог БД 0700 и Unix socket 0660. Не исправляйте проблему правами 0777 |
| Админка на публичном домене возвращает 404 | Ожидаемая защита production. Используйте SSH-туннель и `http://127.0.0.1:8080/admin` |
| Локальная админка через туннель недоступна | Убедитесь, что SSH работает, локальный 8080 свободен и команда туннеля соответствует инструкции VPS. Используйте точный адрес 127.0.0.1:8080 |
| HTTPS-сертификат не выдаётся | Проверьте DNS A/AAAA, доступность 80/443, реальный домен и журналы Caddy. Не добавляйте CDN перед Caddy без пересмотра схемы IP |
| Контейнер unhealthy, но работает | Проверка socket/процесса не прошла. Смотрите app log и Unix socket; сам статус unhealthy не заставляет Compose перезапустить живой процесс |

## Вход и API

| Ответ/симптом | Возможная причина |
| --- | --- |
| 401 при входе | Неверный ключ, лишние символы либо ключ от другой базы/окружения. Сам ключ находится рядом с выбранной SQLite |
| 401 после входа | 30 минут бездействия, 8 часов срока, выход, ротация или вытеснение старой сессии при большом числе входов |
| 403 Origin/Fetch Metadata | Origin отличается от адреса назначения; запрос идёт с другого сайта/порта или соседнего поддомена. Используйте штатный интерфейс |
| 403 CSRF | Устаревший токен после нового входа/ротации. Перезагрузите кабинет и войдите заново |
| 403 при отправке | Токен согласия истёк, уже использован, потерян после рестарта либо изменилась адресная группа клиента. Подтвердите отправку снова |
| 421 | Host не совпадает с разрешённым origin. Проверьте домен, порт, Caddy Host override и origin-конфигурацию |
| 413 / 400 сложность JSON | Превышен размер, глубина, число узлов или строк. Полные ограничения приведены в CONFIGURATION.md |
| 415 | Нужен JSON Content-Type без gzip/br тела |
| 429 | Квота, серия неверных входов или уже выполняющаяся проверка ключа. Учитывайте Retry-After, если он есть; не повторяйте запросы непрерывно |
| 503 | Перегрузка обработчиков либо внутренних ограниченных карт. Проверьте нагрузку и журналы; повышение лимитов без проверки памяти может ухудшить доступность |
| 507 | Число записей или страницы SQLite достигли лимита. Проверьте retention, размеры и свободное место; backup/WAL занимают дополнительный диск |

Квота может делиться между посетителями одного NAT. IPv6-группа — /64. Квоты и токены в памяти сбрасываются при рестарте, однако перезапуск не решает причину перегрузки и не освобождает сохранённые данные.

## Сбор и содержимое отчёта

**Нет новой записи после «Только в браузере».** Это штатное поведение. Для записи нужно отдельное согласие и успешная отправка.

**Не удаётся подтвердить отправку.** Ответ мог потеряться после сохранения. Проверьте кабинет перед повтором; новая отправка с новым токеном может создать дубликат. Идемпотентной операции в API нет.

**Нет камеры, координат или шрифтов.** Проверка требует поддержки браузера, отдельного действия и иногда разрешения/защищённого контекста. Отказ и отсутствие API не означают автоматизацию. Настройки треков камеры/микрофона собираются без записи кадров/звука.

**IP похож на адрес VPN или прокси.** Сервис показывает наблюдаемый адрес соединения, не гарантированный домашний IP устройства. За произвольным дополнительным CDN текущая схема будет видеть его адрес; доверие к новому proxy настраивается отдельно.

**`peerAddress` пустой, `encrypted` false в production.** Node соединяется через Unix socket, TLS завершается на Caddy. Для клиентского адреса смотрите `clientIP`, для схемы — `clientScheme`.

**Хеш изменился или одинаков у разных устройств.** Он вычисляется по ограниченному набору полей, не является уникальным идентификатором и может меняться. Время, IP и параметры соединения в хеш не входят.

**Не найдено сигналов бота.** Это отсутствие проверяемых признаков, а не подтверждение человека. Аналогично наличие WebDriver может означать разрешённый автотест.

## База и резервные копии

**После запуска список пуст.** Проверьте `DATABASE_PATH` и cwd. Запуск из `dist/` без абсолютного пути создаёт отдельную `.data/`; Docker использует свой volume. Ключ из другой базы не подходит.

**Файл не уменьшился после retention.** SQLite может повторно использовать освобождённые страницы без физического уменьшения файла. Старые backups также не удаляются retention-механизмом.

**Backup отказывается перезаписывать файл.** Это ожидаемо. Выберите новое имя. Нужна копия с учётом WAL, а не ручное копирование одного основного SQLite-файла во время работы.

**Backup содержит старые сессии.** Он копирует базу целиком. При восстановлении остановите app/Caddy, следуйте инструкции и выполните ротацию ключа до возобновления доступа.

**Ключ потерян.** При наличии доступа к файловой системе сервера используйте штатную ротацию: она не требует старого ключа и отзывает сессии. Не создавайте новую пустую БД вместо восстановления доступа к существующей.

Подробные команды backup/restore и предупреждение об уничтожении volumes через `down -v` приведены в [инструкции VPS](../DEPLOYMENT.md).

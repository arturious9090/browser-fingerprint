# Модель данных

[Оглавление](README.md) · [API](API.md)

## Три разных источника

| Данные | Источник и доверие |
| --- | --- |
| `report.rows`, `report.profile` | Сообщены клиентом; значения, названия источников и хеш могут быть подделаны |
| `report.signals` | Эвристики пересчитаны сервером по тем же недоверенным клиентским значениям |
| `connection.observations` | Сформированы сервером при сохранении; IP/схема в production наблюдаются Caddy |

Клиентская строка с `source: "server"` не превращается в подтверждённое сервером измерение. Доверенное наблюдение хранится отдельно в `connection`.

## Нормализованный отчёт, schemaVersion 1

| Поле | Значение |
| --- | --- |
| `schemaVersion` | Число `1` |
| `createdAt` | Валидное клиентское время приведено к ISO UTC; иначе `null` |
| `rows` | От 1 до 2000 строк с уникальными `id` |
| `profile` | Допустимый клиентский SHA-256-профиль либо `null` |
| `signals` | Массив сформированных сервером сигналов |
| `trust` | Пояснение, что значения и source строк не подтверждают подлинность |

### Строка параметра

| Поле | Требование или нормализация |
| --- | --- |
| `id` | Строка 1–240 символов, уникальна в отчёте; без ASCII control/DEL |
| `key` | Сервер устанавливает равным `id` |
| `label` | Клиентская строка до 240 символов; иначе `id` |
| `value` | JSON-значение; отсутствующее/`null` становится `null`; сериализация до 400 000 символов |
| `status` | Одно из значений ниже |
| `source` | `browser`, `server`, `edge`, `optional` или `observation` |
| `category` | Одна из допустимых категорий ниже |
| `note` | Строка до 2000 символов; иначе пустая |
| `durationMs` | Конечное число, минимум 0; некорректное становится 0 |

| Status | Смысл |
| --- | --- |
| `ok` | Проверка получила значение |
| `unsupported` | API/возможность не поддерживается |
| `blocked` | Доступ запрещён разрешением или политикой браузера |
| `error` | Проверка завершилась ошибкой |
| `timeout` | Время ожидания исчерпано |
| `unavailable` | Данных нет или API их не раскрыл |

Категории строк: `browser`, `device`, `locale`, `graphics`, `audio`, `fonts`, `media`, `storage`, `permissions`, `capabilities`, `network`, `server`, `behavior`, `optional`. В интерфейсе также существуют `all` и `automation` как представления; передавать их в `row.category` нельзя.

Общий предел JSON: глубина 16 и 30 000 узлов. Проверка применяется к полному запросу, включая обёртку согласия; запрещены ключи `__proto__`, `prototype`, `constructor`. Тело HTTP и число строк ограничиваются дополнительно.

### Хеш профиля

Клиент выбирает успешные значения из фиксированного списка 20 характеристик, сортирует их по ID и вычисляет SHA-256 JSON-представления. В список входят User-Agent, платформа, аппаратные оценки, экран, timezone, Canvas/WebGL/audio и шрифты. Точный список — `profileHash` в `public/collector.js`; IP, часы запроса и объём хранилища туда не входят.

Сервер принимает `profile.hash` только как 64 строчных hex-символа, фиксирует `algorithm: "SHA-256"`, ограничивает `fields` сотней существующих строк отчёта и добавляет пояснение. Он не пересчитывает этот хеш и не подтверждает его уникальность. Если хеш некорректен, `profile` становится `null`.

### Сигналы

Сигнал содержит `id`, `strength`, `title`, `evidence`, `explanation`, `falsePositives`, `fields`. Степени — `strong`, `moderate`, `context`; числовой вероятности бота нет.

Основные эвристики: WebDriver, headless-маркер, исторические Phantom/Selenium/ChromeDriver-глобалы, программный GPU, нестабильный Canvas, противоречие UA/Client Hints и особенности размеров окна. Код также понимает некоторые строки внешних edge-данных, но клиентская строка с ними не является достоверным ответом провайдера. В поставленной Node/Caddy-схеме внешний bot score не подключён.

## Серверное наблюдение

`connection` имеет поле `observations`. Оно включает время наблюдения, HTTP-метод и версию непосредственного запроса, socket-адреса/порты, состояние TLS на Node, безопасные HTTP-заголовки, `clientIP`, `clientScheme`, `forwardedHeadersTrusted` и область применимости наблюдения.

В production Node видит Unix socket, поэтому TCP-поля могут быть `null`. `clientIP` передаётся Caddy по этому socket; публичный TLS завершается на Caddy. `encrypted: false` на Node в такой схеме нормально и не означает отсутствие HTTPS у посетителя.

Недоступные измерения оформляются объектом:

```json
{"__result":true,"status":"unavailable","value":null,"note":"Причина недоступности"}
```

Cookie, Authorization, ключи и произвольные заголовки не включаются в `requestHeaders`. JA3/JA4, ASN и тип прокси не вычисляются этой схемой. WebRTC-проверка без внешнего STUN не подменяет серверный публичный IP.

## SQLite

Файл по умолчанию — `.data/fingerprints.sqlite` относительно рабочего каталога; в Docker — `/data/fingerprints.sqlite`. Ключ находится рядом в `owner-key.txt`. Текущий `PRAGMA user_version` — 1.

### reports

| Колонки | Содержание |
| --- | --- |
| `id` TEXT PRIMARY KEY | 16 случайных байт в hex, 32 символа |
| `created_at` TEXT | Серверное ISO-время записи; основа сортировки и retention |
| `consent_at`, `consent_version`, `consent_text` TEXT | Серверное время выдачи согласия, его версия и точный текст |
| `fingerprint` TEXT nullable | Клиентский `profile.hash`, если принят |
| `ip` TEXT nullable | Наблюдаемый clientIP, при его отсутствии peerAddress |
| `user_agent` TEXT | Строка из `navigator.userAgent`, максимум 2048 символов; иначе пустая |
| `row_count`, `signal_count` INTEGER | Число нормализованных строк и пересчитанных сигналов |
| `report_json`, `connection_json` TEXT | Полные структуры отчёта и серверного наблюдения |
| `revoke_hash` TEXT | Legacy-колонка; в новых записях пустая строка, публичный отзыв удалён |

Индекс `reports_created` построен по `created_at DESC`. Список возвращает метаданные, детальная запись распаковывает JSON и исключает legacy-хеш.

### owner

Одна строка с `id=1`, `salt` и `hash`. Ключ — 32 случайных байта в base64url; соль — 24 случайных байта в hex; scrypt выдаёт 64 байта, записанные как hex. Открытый ключ в таблице не хранится, но есть в закрытом файле владельца.

### sessions

`token_hash` TEXT PRIMARY KEY, `csrf` TEXT, `created_at`, `touched_at`, `expires_at` INTEGER. Времена — Unix milliseconds. Session-токены случайные, в БД сохраняется их SHA-256; CSRF хранится в строке сессии. Создание сессии выполняется транзакционно, ограничивает их число и проверяет неизменность credential после дорогой проверки ключа.

## Хранение и копирование

SQLite использует WAL, busy timeout 5000 мс, foreign_keys и secure_delete. WAL автоматически checkpoint-ится после 1000 страниц; journal_size_limit — 16 МиБ, это не общий жёсткий предел текущего WAL.

`MAX_DATABASE_BYTES` ограничивает страницы основной БД, `MAX_REPORTS` — количество строк reports. Оба лимита независимы. WAL и backups требуют дополнительного места. При уменьшении лимита ниже уже занятого размера SQLite не обязана физически сократиться.

Retention удаляет до 500 записей за проход по серверному `created_at`, а не клиентскому времени. Освободившиеся страницы могут использоваться повторно без уменьшения файла. Backups имеют собственный срок хранения и автоматически этим механизмом не очищаются.

Согласованную копию работающей WAL-базы создаёт `scripts/backup.mjs`; копирование только основного файла не является заменой backup. Восстановление и обязательная ротация ключа описаны в [инструкции VPS](../DEPLOYMENT.md).

При старте выполняется `CREATE TABLE IF NOT EXISTS`; полноценного механизма версионированных миграций пока нет. Для изменения схемы нужны отдельный план миграции, backup, проверка на существующей БД и тест восстановления. Одного изменения `user_version` недостаточно.

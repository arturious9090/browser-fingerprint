# HTTP API

[Оглавление](README.md) · [Модель данных](DATA-MODEL.md)

API предназначен для интерфейса на том же origin. Это не публичный межсайтовый API: разрешающие CORS-заголовки не выдаются. В production административные маршруты доступны только на локальном origin SSH-туннеля.

## Общие правила

- JSON-запросы: `Content-Type: application/json`; сжатые тела не поддерживаются.
- Все изменяющие запросы требуют точного `Origin`, соответствующего адресу назначения. API также отвергает `Sec-Fetch-Site: cross-site` и `same-site`.
- GET API с указанным Origin требует такого же точного совпадения. При отсутствии Fetch Metadata остаются проверки Origin и сессии/CSRF.
- Административные изменения, кроме входа, дополнительно требуют `X-CSRF-Token` и cookie `fp_admin`.
- Ответы Node API имеют JSON Content-Type и `Cache-Control: no-store`. Caddy может отклонить запрос раньше Node; такой ответ не обязан быть JSON.
- `X-Request-ID` Node содержит случайный идентификатор запроса. Ошибки не раскрывают стеки и ключи.

HTTP HEAD поддерживается для статических файлов, `/api/ping` и `/api/admin/connection`. Для остальных API таблица ниже описывает реализованные методы; неподдерживаемый метод API обычно попадает в 404, а не в универсальный обработчик 405.

## Карта маршрутов

| Метод | Путь | Доступ | Результат |
| --- | --- | --- | --- |
| GET | `/healthz` | Публичный | Liveness процесса, `200 {"ok":true}` |
| GET, HEAD | `/api/ping` | Публичный | `200 {"ok":true}`, измерение HTTP round-trip |
| GET | `/api/config` | Публичный | Текущий текст/версия согласия |
| POST | `/api/consent` | Публичный, same-origin | Одноразовый токен отправки |
| POST | `/api/reports` | Публичный, с согласием | Сохранение отчёта, `201 {"saved":true}` |
| POST | `/api/admin/login` | Только административный origin в production | Создание сессии владельца |
| GET | `/api/admin/session` | Сессия владельца | CSRF и срок сессии |
| POST | `/api/admin/logout` | Сессия и CSRF | Отзыв текущей сессии |
| GET | `/api/admin/reports` | Сессия владельца | Поиск и пагинация записей |
| GET | `/api/admin/reports/:id` | Сессия владельца | Одна запись целиком |
| GET, HEAD | `/api/admin/connection` | Сессия владельца | Текущее наблюдение соединения |

`/api/connection`, публичные GET/DELETE `/api/reports/:id` и административный API удаления не реализованы. Старые токены удаления не дают доступа. На публичном production-origin все `/api/admin/*` закрыты даже при наличии cookie.

## Согласие и отправка

### GET /api/config

```json
{
  "storageAvailable": true,
  "consentVersion": "2026-10-19-v2",
  "consentText": "Текущий полный текст согласия из public/consent.js"
}
```

Версия приведена для текущего кода. Клиент должен использовать актуальную версию, а не навсегда фиксировать строку из примера. `storageAvailable` — признак наличия функции сохранения, не проверка свободного диска или квоты.

### POST /api/consent

Тело до 4096 байт:

```json
{"granted":true,"version":"2026-10-19-v2"}
```

Успех — 201:

```json
{"uploadToken":"<случайный одноразовый токен>","expiresInSeconds":600}
```

Токен связан с точным origin и адресной группой клиента, хранится только в памяти сервера в виде хеша. Одновременно допускается до 2000 неистёкших токенов. Перезапуск процесса делает ранее выданные токены недействительными.

### POST /api/reports

Тело до 2 097 152 байт:

```json
{
  "consent":{"granted":true,"version":"2026-10-19-v2"},
  "uploadToken":"<токен из предыдущего ответа>",
  "report":{
    "schemaVersion":1,
    "createdAt":"2026-10-21T10:00:00.000Z",
    "rows":[
      {
        "id":"navigator.webdriver",
        "label":"webdriver",
        "category":"browser",
        "source":"browser",
        "status":"ok",
        "value":false,
        "note":"Демонстрационный параметр",
        "durationMs":1
      }
    ]
  }
}
```

Успех — 201, строго без ID и ключей удаления:

```json
{"saved":true}
```

После успешной записи токен расходуется. Новый токен и тот же отчёт создают новую запись; дедупликации и idempotency key нет. Сбой сети после записи может оставить посетителя без подтверждения, хотя данные уже сохранены.

Поле `report.signals` серверу не доверяется: оно пересчитывается. `profile` необязателен, клиентский `createdAt` не используется как время хранения. Формат строк и нормализация описаны в [модели данных](DATA-MODEL.md).

### Пример последовательности в браузере

Пример намеренно создаёт одну тестовую запись. Выполняется только на странице самого сервиса после осознанного выбора отправки; он не заменяет пользовательское окно согласия.

```js
const config = await fetch('/api/config').then(r => r.json());
const post = async (url, body) => {
  const response = await fetch(url, {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify(body)
  });
  const result = await response.json();
  if (!response.ok) throw new Error(result.error);
  return result;
};
const consent = {granted: true, version: config.consentVersion};
const ticket = await post('/api/consent', consent);
await post('/api/reports', {
  consent,
  uploadToken: ticket.uploadToken,
  report: {
    schemaVersion: 1,
    rows: [{id: 'navigator.webdriver', value: false,
      category: 'browser', source: 'browser', status: 'ok'}]
  }
});
```

Браузер формирует Origin самостоятельно. Для собственного HTTP-клиента его нужно передать явно. Предпочтительный способ работы владельца — штатный кабинет, без передачи ключей в URL или командную историю.

## Административная сессия

### POST /api/admin/login

JSON до 4096 байт, поле `key` — строка длиной 32–256 символов. Настоящий ключ создаётся сервером и не содержится в документации.

Успех — 200:

```json
{"authenticated":true,"csrfToken":"<случайный CSRF-токен>"}
```

В `Set-Cookie`: `fp_admin`, HttpOnly, SameSite=Strict, Path=/api/admin, Max-Age=28800; Secure для HTTPS. На локальном HTTP-origin админки Secure отсутствует: удалённый участок связи защищает SSH-туннель. Атрибут Domain не устанавливается.

Повторный успешный вход отзывает предъявленную старую сессию и создаёт новую. В БД токен хранится как SHA-256. Всего остаётся до 16 сессий; срок — до 8 часов и 30 минут бездействия.

### GET /api/admin/session

С cookie владельца возвращает 200:

```json
{"authenticated":true,"csrfToken":"<токен>","expiresAt":1792600000000}
```

`expiresAt` — абсолютный срок в Unix milliseconds. Успешные обращения к защищённому API обновляют время активности; после отзыва или истечения — 401.

### POST /api/admin/logout

Передайте cookie, корректный Origin, `X-CSRF-Token`. Штатный клиент посылает `{}`. Успех — `200 {"authenticated":false}` и удаляющий cookie с Max-Age=0. Старый session-токен больше не принимается.

## Чтение отчётов владельцем

### GET /api/admin/reports

| Query | По умолчанию | Поведение |
| --- | --- | --- |
| `q` | Пустая строка | До 256 символов; поиск по IP, User-Agent, хешу и ID. `%` и `_` считаются буквальными символами |
| `limit` | 25 | Приводится к числу, ограничивается 1–100, округляется вниз |
| `offset` | 0 | Приводится к числу, ограничивается 0–1 000 000, округляется вниз |

Для `limit=0` или нечислового значения используется 25; `offset` с нечисловым значением становится 0. Порядок — `created_at DESC, id DESC`.

```json
{
  "total":1,
  "limit":25,
  "offset":0,
  "reports":[{
    "id":"0123456789abcdef0123456789abcdef",
    "created_at":"2026-10-21T10:00:01.000Z",
    "consent_at":"2026-10-21T10:00:00.000Z",
    "consent_version":"2026-10-19-v2",
    "fingerprint":null,
    "ip":"192.0.2.10",
    "user_agent":"Example Browser",
    "row_count":1,
    "signal_count":0
  }]
}
```

### GET /api/admin/reports/:id

ID — 32 строчных hex-символа. Успех возвращает метаданные, `consent_text`, нормализованный `report` и `connection`. Служебный `revoke_hash` не выдаётся. Неизвестный или некорректный ID — 404 после проверки доступа.

JSON-экспорт выполняется браузером из уже полученной записи: отдельного HTTP download-маршрута нет.

### GET /api/admin/connection

Возвращает `{"observations":{...}}`: серверное время, непосредственное соединение Node, разрешённые заголовки, `clientIP`, `clientScheme`, признак доверия к proxy-наблюдениям и явно недоступные измерения. Это текущий административный запрос, а не соединение выбранного посетителя. Его наблюдение сохранено в `connection` соответствующей записи.

## Ошибки и ограничения

Обычная ошибка Node API:

```json
{"error":"Текст ошибки","requestId":"0123456789abcdef"}
```

| Код | Типичная причина |
| --- | --- |
| 400 | JSON, схема, версия/признак согласия или схема proxy-соединения некорректны |
| 401 | Неверный ключ либо отсутствующая/истёкшая сессия |
| 403 | Origin/Fetch Metadata/CSRF, использованный или истёкший токен, смена адресной группы |
| 404 | Маршрут/запись отсутствует; production-админка запрошена на публичном домене |
| 405 | Неподдерживаемый метод статического маршрута |
| 413 | Слишком большое тело |
| 414 | Слишком длинный URL |
| 415 | Неверный Content-Type либо сжатое тело |
| 421 | Host не соответствует разрешённому origin |
| 429 | Квота либо параллельная проверка входа; Retry-After есть у отказов лимитера |
| 500 | Внутренняя ошибка без стека и секретов |
| 503 | Перегрузка обработчиков, лимитера или выдачи токенов |
| 507 | Лимит записей/страниц SQLite достигнут |

`/healthz` подтверждает работоспособность HTTP-процесса, а не возможность новой записи, свободное место или успешность backup. Все квоты и ограничения тела/структуры — в [справочнике конфигурации](CONFIGURATION.md).

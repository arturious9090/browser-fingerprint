# Конфигурация

[Оглавление](README.md) · [Запуск VPS](../DEPLOYMENT.md)

## Как применяются настройки

Прямой запуск Node читает окружение процесса. `npm start` сам не загружает `.env`. Передавайте переменные перед командой или экспортируйте их в окружение. Compose автоматически читает `.env` для подстановки значений в `compose.yaml`.

```sh
PORT=4174 DATABASE_PATH=/absolute/private/fingerprints.sqlite npm start
```

В production скопируйте `.env.example` в `.env`, укажите домен и email, затем используйте Compose по инструкции. Образ зафиксирован по digest; изменение переменных требует пересоздания контейнера, изменение кода — пересборки образа. В dev после изменения окружения также нужен новый процесс.

## Переменные процесса Node

| Переменная | По умолчанию | Условия |
| --- | --- | --- |
| `NODE_ENV` | Не задана: dev | Строгие production-проверки включаются при точном значении `production` |
| `HOST` | `127.0.0.1` | Для TCP dev-запуска; production Compose использует socket вместо TCP |
| `PORT` | `4173` | Целое 1–65535, если используется TCP |
| `DATABASE_PATH` | `.data/fingerprints.sqlite` от cwd | В Compose `/data/fingerprints.sqlite`; рекомендуйте абсолютный путь при нескольких каталогах запуска |
| `PUBLIC_ORIGIN` | Не задан | В dev разрешены локальные адреса текущего порта; в production обязателен HTTPS-origin |
| `ADMIN_ORIGIN` | `http://127.0.0.1:8080` | В production только loopback HTTP; должен совпадать с конфигурацией локального входа Caddy |
| `PROXY_SOCKET` | Не задан | В production обязателен абсолютный путь; в Compose `/run/fingerprint/app.sock` |
| `REQUESTS_PER_MINUTE` | `240` | Целое 1–10 000, запросы на адресную группу за минуту |
| `UPLOADS_PER_HOUR` | `30` | Целое 1–10 000; отдельные квоты согласий и попыток отправки на адресную группу за час |
| `GLOBAL_UPLOADS_PER_HOUR` | `1000` | Целое 1–100 000; попытки отправки на весь процесс за час |
| `MAX_REPORTS` | `10000` | Целое 1–1 000 000; предел сохранённых записей |
| `MAX_DATABASE_BYTES` | `536870912` | Целое 1 048 576–17 179 869 184; предел страниц основной SQLite, от 1 МиБ до 16 ГиБ |
| `RETENTION_DAYS` | Dev: `0`, production: `30` | Целое 0–3650; `0` отключает автоматическое удаление |

Origin — только схема и адрес с необязательным портом, без пути, query, hash и встроенного пароля. Например, `https://fingerprint.example.com`. Нелокальный HTTP для `PUBLIC_ORIGIN` запрещён и в dev. Production не стартует без HTTPS-origin и Unix socket. Каталог production-базы должен быть закрыт правами 0700; файл БД/ключ — 0600.

В поставляемом Compose `PUBLIC_ORIGIN`, `ADMIN_ORIGIN`, `DATABASE_PATH`, `PROXY_SOCKET`, `NODE_ENV` заданы самим YAML. Изменение одноимённого значения только в `.env` их не переопределяет, если YAML не использует такую подстановку. Для другой топологии меняйте согласованно Compose, Caddyfile и настройки приложения.

## Переменные Compose/Caddy

| Переменная `.env` | Назначение |
| --- | --- |
| `DOMAIN` | Обязательное доменное имя без `https://` и пути, например `fingerprint.example.com` |
| `ACME_EMAIL` | Обязательный email для ACME/Caddy |
| Шесть числовых настроек из `.env.example` | Retention, ёмкость базы и квоты; передаются app через Compose |

`.env.example` содержит `RETENTION_DAYS`, `MAX_REPORTS`, `MAX_DATABASE_BYTES`, `UPLOADS_PER_HOUR`, `GLOBAL_UPLOADS_PER_HOUR`, `REQUESTS_PER_MINUTE` — шесть числовых настроек. Ключ владельца через env не передаётся: он создаётся в закрытом volume. `HOST` и `PORT` для app-контейнера не нужны.

## Постоянные ограничения

Эти значения заданы кодом и не меняются через `.env`:

| Ограничение | Значение |
| --- | --- |
| Тело отчёта | 2 097 152 байта |
| Тело входа или согласия | 4096 байт |
| URL | До 2048 символов |
| HTTP-заголовки Node | 16 КиБ; в объекте заголовков учитывается до 100 |
| Параллельные обработчики Node | 8, без учёта раннего liveness |
| HTTP-соединения Node | До 256 |
| Запросы на одно keep-alive соединение | До 100 |
| Заголовки / весь запрос Node | 10 / 30 секунд |
| Чтение JSON-тела | До 15 секунд |
| Keep-alive Node | 5 секунд |
| Глубина / узлы JSON | 16 / 30 000 |
| Строки отчёта | 1–2000 |
| Одноразовое согласие | 10 минут, до 2000 активных токенов |
| Общая квота согласий | `2 × GLOBAL_UPLOADS_PER_HOUR` в час |
| Вход на адресную группу | 5 попыток за 15 минут |
| Вход на весь процесс | 30 попыток за 15 минут |
| Дорогая проверка ключа | Одна одновременно |
| Сессии | До 16; бездействие 30 минут; общий срок 8 часов |
| Карта лимитера | До 10 000 ключей |
| Автоочистка | При старте и каждые 10 минут, максимум 500 записей за проход |
| Аудит | До 10 записей каждого типа в минуту; следующий интервал сообщает число подавленных |
| Остановка процесса | До 10 секунд перед принудительным завершением соединений |

Квоты используют фиксированные временные окна. Неверные попытки тоже их расходуют; новые токены согласия не обходят квоту отправки. IPv4 ограничивается по адресу, IPv6 — по /64. Резидентские прокси с множеством адресов могут исчерпать общую квоту; за NAT несколько посетителей делят одну адресную квоту.

Лимитеры и одноразовые токены находятся в памяти процесса и сбрасываются при рестарте. SQLite-отчёты и сессии сохраняются на диске.

## Ограничения Docker

App: 384 МиБ RAM, 1 CPU, 64 PID; Caddy: 256 МиБ, 1 CPU, 128 PID. Backup/maintenance: по 192 МиБ, 1 CPU, 32 PID. Это стартовые значения для небольшого сервиса, а не подтверждённая нагрузочная ёмкость VPS.

Корневые файловые системы read-only; разрешены только необходимые volumes/tmpfs. Docker-журнал — до трёх файлов по 10m. Проверки состояния app идут каждые 30 секунд с тайм-аутом 5 секунд; окно запуска 15 секунд, три неудачи до unhealthy. `restart: unless-stopped` перезапускает завершившийся процесс, но сам статус unhealthy не является автоматическим перезапуском.

Caddy ограничивает тело 2 097 152 байт, заголовки 16KB и задаёт read_header 10s, read_body/write/idle 30s. Актуальные сетевые настройки находятся в `deploy/Caddyfile`.

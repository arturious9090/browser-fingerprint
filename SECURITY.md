# Безопасность сервиса

[Оглавление документации](docs/README.md) · [Архитектура](docs/ARCHITECTURE.md)

## Границы доверия

Браузерные отпечатки, их хеши, названия источников и сигналы посетитель может подделать. Они хранятся как сообщения клиента, а не подтверждение личности или отсутствия автоматизации. Сервер пересчитывает эвристики и хранит собственное наблюдение соединения отдельно.

Production-приложение запускается только с явным HTTPS `PUBLIC_ORIGIN`, локальным `ADMIN_ORIGIN` и Unix `PROXY_SOCKET`. Сетевого порта у app-контейнера нет. Caddy перезаписывает Host, X-Real-IP и схему для каждой точки входа. Node доверяет этим сведениям только при соединении через Unix socket. X-Forwarded-For, Forwarded, CF-* и клиентские bot score не дают дополнительных полномочий.

На публичном origin закрыты страницы и API владельца в Caddy и в приложении. Админ-вход — через loopback-порт и SSH, плюс случайный ключ 256 бит. SQLite хранит scrypt-хеш ключа и хеши session-токенов. Сессии ограничены по числу, бездействию и абсолютному сроку; ротация ключа отзывает все сессии. CSRF проверяется для изменений владельца, Origin/Fetch Metadata — для API; соседние поддомены не считаются доверенными. Origin не является доказательством согласия человека: оно фиксируется по действию интерфейса, а автоматический клиент может отправить такой же запрос.

## Защита HTTP и хранения

- Статические файлы выдаются только по allowlist и читаются при старте. Базы, env, исходники сервера, backups и ключи не обслуживаются по HTTP.
- CSP запрещает внешние скрипты и inline-код; frame-ancestors, X-Frame-Options, CORP/COOP, no-sniff, no-referrer, no-store, HSTS на HTTPS. Секретные заголовки не входят в отчёты.
- Контроль Host и схемы, размера URL/заголовков/тела, тайм-ауты, предел подключений и параллельных обработчиков. Сжатый JSON не принимается. Сложность JSON и число строк ограничены; недоверенные значения выводятся через textContent.
- Ограничены запросы, выдача согласий, попытки сохранения и входа; есть общие квоты против распределённого заполнения. Одноразовое согласие связано с origin и адресной группой клиента, живёт 10 минут.
- SQL использует параметры. SQLite имеет лимит страниц и числа записей, production — настраиваемую очистку по сроку. Ключ и БД имеют 0600; production-каталог требует 0700. Backup-volume не подключён к постоянно работающему app; онлайн-копию создаёт отдельная задача с read-only доступом к БД. Контейнер app работает с UID 1000, без сети, привилегий и записи в корневую ФС.
- Журнал безопасности фиксирует входы, выходы, отказы доступа, чтение отчётов и превышение квот. Записи содержат время, фиксированный тип события, случайный request ID и статус — без ключей, токенов, URL, тел запросов и IP. Частота записей ограничена, чтобы атака не раздувала журнал. Access log Caddy не включён. Docker-журналы ротируются. Операционные ошибки Caddy могут содержать сведения о запросах; ограничьте доступ к Docker и его журналам.

## Остаточные риски и эксплуатация

Это подготовленная конфигурация для одного VPS, а не гарантия отсутствия уязвимостей. Хост и Docker-администратор имеют доступ к данным; полного шифрования БД и защиты от компрометации VPS здесь нет. Используйте шифрование диска у провайдера и защищённое внешнее хранение backups. HTTPS-сертификат и внешние порты необходимо проверить на реальном домене после запуска.

Квоты в памяти сбрасываются при рестарте; много адресов может исчерпать общую квоту и временно закрыть приём. Они не заменяют защиту от сетевого DDoS. Пределы памяти/CPU выбраны для небольшого сервиса, нагрузочная ёмкость VPS должна проверяться отдельно. SSH-туннель является обязательным барьером админ-доступа в поставленной конфигурации; публичный ключевой вход без туннеля не поддерживается.

Хранение после согласия не делает любой сценарий использования законным автоматически. До запуска настройте уведомление о данных, контакт владельца и реальные сроки хранения. Не включайте сбор дополнительных разрешений автоматически. У посетителя нет публичного API чтения, экспорта или удаления — это сохраняет выбранное владельцем поведение.

В случае утечки ключа выполните `admin:rotate`, проверьте доступ к VPS и резервным копиям. При компрометации хоста ротации одного ключа недостаточно: восстановите доверенную среду. Порядок запуска, backup и восстановления находится в [DEPLOYMENT.md](DEPLOYMENT.md).

# Практики безопасности и их применение

[Оглавление документации](docs/README.md) · [Безопасность](SECURITY.md)

Сверено с первичными источниками 21 октября 2026. Это описание принятых мер и проверок, а не сертификат OWASP или гарантия отсутствия уязвимостей. Проверка реального домена и VPS выполняется после развёртывания по DEPLOYMENT.md.

| Практика | Что сделано в приложении | Основание |
| --- | --- | --- |
| Изолировать управление от публичного трафика | Production-админка недоступна на публичном origin и в Caddy, и в Node. Доступ — loopback-порт через SSH и отдельный случайный ключ. | [OWASP REST: Management endpoints](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html#management-endpoints) |
| Проверять полномочия на каждом приватном маршруте | Все `/api/admin/` кроме входа требуют сессии. Публичное чтение/удаление сохранённых записей отсутствует; ID не возвращается при отправке. | [OWASP REST: Access control](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html#access-control) |
| Защищать сессии | 256 случайных бит, токены в БД хешированы; HttpOnly, SameSite Strict, без Domain, ограниченные сроки и число сессий; новый токен при входе, отзыв при выходе/ротации. Secure используется для HTTPS. Loopback HTTP админки защищён SSH-туннелем, а не публичным HTTP. | [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) |
| Не полагаться только на SameSite | Проверяется точный Origin, Fetch Metadata отвергает cross-site и same-site API-запросы; изменения владельца требуют CSRF-токен. При отсутствии Fetch Metadata остаются Origin и CSRF. | [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) |
| Ограничивать недоверенный ввод и ресурсы | JSON-only, лимиты тела/глубины/узлов/строк, запрет опасных ключей и сжатых тел; квоты запросов/отправок, общие лимиты, тайм-ауты. SQLite ограничена по страницам и количеству записей. | [OWASP REST: Input validation](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html#input-validation), [OWASP DoS](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html) |
| Не доверять proxy-заголовкам посетителя | App работает без TCP-интерфейса. Только Unix socket разрешает принимать X-Real-IP/схему от Caddy; Caddy перезаписывает их. Клиентские XFF, CF-* и bot score не дают доверенных сведений. | [Caddy reverse_proxy: Headers](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#headers) |
| Шифровать публичный транспорт | Caddy автоматически получает/продлевает сертификат, перенаправляет HTTP на HTTPS. HTTPS-ответы приложения содержат HSTS. Production не стартует без HTTPS-origin и отдельного socket. | [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https) |
| Снижать риск XSS и инъекций | Значения выводятся через textContent; нет HTML из отчётов. CSP без inline/eval/внешних скриптов, frame-ancestors none, nosniff, CORP/COOP. SQL-параметры отделены от текста запросов; поиск экранирует SQL wildcard. | [OWASP XSS Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html), [OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html) |
| Минимизировать права контейнеров | App: UID 1000, network none, read-only root, cap_drop ALL, no-new-privileges, лимиты CPU/RAM/PID. Caddy получает только нужный socket, без БД и ключа. Корневая ФС Caddy read-only, capability только NET_BIND_SERVICE. | [OWASP Docker Security](https://cheatsheetseries.owasp.org/cheatsheets/Docker_Security_Cheat_Sheet.html), [Docker Compose services](https://docs.docker.com/reference/compose-file/services/) |
| Журналировать безопасность, исключать секреты | Фиксируются входы, выходы, отказы сессии/CSRF/Origin, чтение отчётов, квоты и ошибки. Только время, тип, случайный request ID, статус. Нет IP, URL, ключей, cookies и тел. Частота событий ограничена; Docker-журнал ротируется. | [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) |
| Готовить восстановление | SQLite online backup учитывает WAL и проверяется quick_check. Backup-volume не доступен постоянно работающему app; отдельная задача видит БД read-only. Восстановление выполняется при остановке сервиса и отзывает старые сессии ротацией ключа. | [Node SQLite backup](https://nodejs.org/api/sqlite.html#sqlitebackupsource-db-path-options) |
| Поддерживать обновления | Node 24 LTS и официальные Docker-образы, зафиксированные по digest; у приложения нет npm-зависимостей. Сборка запускает регрессионные тесты. Требуется регулярное обновление digests и пересборка базовых образов и проверка релиза. | [Node releases](https://nodejs.org/en/about/previous-releases), [OWASP Docker Security](https://cheatsheetseries.owasp.org/cheatsheets/Docker_Security_Cheat_Sheet.html) |

## Что зависит от эксплуатации

Защита провайдера от DDoS, обновления VPS/Docker, SSH-ключи и сетевой экран, оповещения о заполнении диска/5xx, шифрованные внешние backups и подходящий срок их хранения настраиваются на реальном сервере. Доступ к Docker практически равен административному доступу к данным: не выдавайте его посторонним и не монтируйте Docker socket в сервис.

Публичные API сохраняют сообщения клиента, а не доказывают участие человека. Злоумышленник с множеством адресов способен заполнить общую квоту. Это ограничит запись, но не заменит edge-защиту и анализ нагрузки. Все ограничения и особенности хранения перечислены в SECURITY.md и DEPLOYMENT.md.

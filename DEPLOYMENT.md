# Запуск на VPS: Docker + HTTPS

[Оглавление документации](docs/README.md) · [Конфигурация](docs/CONFIGURATION.md) · [Диагностика проблем](docs/TROUBLESHOOTING.md)

Конфигурация рассчитана на один Linux VPS и один экземпляр приложения. У Node.js нет сетевого интерфейса: Caddy обращается к нему по Unix socket в общем Docker volume. SQLite, ключ владельца и резервные копии находятся в отдельных volumes, которые Caddy не получает.

Публичный домен обслуживает посетителей. Админ-панель закрыта на публичном домене и доступна через SSH-туннель на `http://127.0.0.1:8080/admin`. Вход по случайному ключу нужен и через туннель.

## 1. Домен и сервер

Нужен VPS с Docker Engine и Compose v2, свободными портами 80/443 и примерно 1 ГБ RAM для контейнеров и ОС. A-запись домена должна указывать на VPS; AAAA добавляйте только при работающем IPv6. Эта конфигурация предполагает прямой доступ к Caddy, без CDN перед ним.

В сетевом экране VPS разрешите входящие 80/tcp, 443/tcp, 443/udp и SSH со своего адреса. Порт 8080 привязан Compose только к `127.0.0.1`; не меняйте его на `0.0.0.0`. Порта приложения в Compose нет. Docker может обходить некоторые правила UFW: проверяйте именно опубликованные Docker-порты и внешний сетевой экран провайдера.

Передайте на VPS исходники без `.data`, `.env`, `dist` и локальных баз. В каталоге проекта:

```sh
cp .env.example .env
chmod 600 .env
```

В `.env` замените `DOMAIN` и `ACME_EMAIL` на свои значения. Секретных ключей в `.env` нет; ключ владельца создаётся внутри закрытого volume при первом запуске.

## 2. Проверка и запуск

```sh
docker compose config --quiet
docker compose pull caddy
docker compose build --pull
docker compose run --rm --no-deps caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose up -d
docker compose ps
docker compose logs --tail=50 app caddy
```

Образ приложения собирается только после прохождения автотестов. Для отдельной проверки всей схемы на машине с Docker: `docker build -t fingerprint-security-check:local .`, затем `node scripts/smoke-docker.mjs`. Скрипт использует случайные loopback-порты, временный локальный CA и отдельные volumes; реальные данные и публичный выпуск сертификата не затрагиваются. Caddy получает и продлевает сертификат автоматически; для этого домен должен уже указывать на VPS и порты 80/443 должны быть доступны. Не используйте эту production-конфигурацию для локальной проверки сертификата вымышленного домена.

Проверьте с другой сети:

```sh
curl -I https://YOUR_DOMAIN/
curl -o /dev/null -w '%{http_code}\n' https://YOUR_DOMAIN/admin
curl -o /dev/null -w '%{http_code}\n' https://YOUR_DOMAIN/api/admin/reports
```

Первая команда должна вернуть 200 и защитные заголовки, следующие — 404. Обычный HTTP перенаправляется на HTTPS. После отказа посетителя от отправки в админ-панели не должно появляться новой записи; после согласия должна появиться запись с IP клиента, а не IP контейнера.

## 3. Вход владельца

На своём компьютере откройте туннель и оставьте SSH-команду работающей:

```sh
ssh -N -L 127.0.0.1:8080:127.0.0.1:8080 USER@VPS
```

Откройте `http://127.0.0.1:8080/admin` (именно этот адрес). Получите ключ в своей SSH-сессии на VPS:

```sh
docker compose exec -T app cat /data/owner-key.txt
```

Сохраните его в менеджере паролей. Не отправляйте вывод в сообщения, скриншоты, журналы или репозиторий. HTTP здесь используется только на loopback и внутри локального Unix socket; участок между компьютером и VPS шифруется SSH. Cookie на этом локальном origin — HttpOnly/SameSite=Strict, без Secure, чтобы вход работал через loopback HTTP. На HTTPS-origin сервер ставит Secure.

Смена ключа с отзывом всех сессий:

```sh
docker compose exec -T app node scripts/rotate-owner.mjs
```

Новый ключ снова прочитайте из `/data/owner-key.txt`. Ключ остаётся вне образа и не попадает в HTTP-ответы.

## 4. Лимиты и хранение

Параметры находятся в `.env.example`. По умолчанию: до 30 попыток отправки и согласия на IP в час, 1000 попыток отправки на весь сервис в час, 240 запросов на IP в минуту, не более 10 000 записей, SQLite до 512 МиБ. IPv6 ограничивается по /64. Неверные запросы тоже расходуют квоту. За NAT лимит делится между посетителями; при смене адреса после согласия потребуется подтвердить отправку снова.

В production включено удаление записей старше 30 дней по серверному времени сохранения: при старте и каждые 10 минут, партиями до 500. `RETENTION_DAYS=0` отключает автоочистку. Изменение применяется после пересоздания контейнера. Локальный dev-запуск по умолчанию ничего не очищает. Текст согласия и ваша политика хранения должны соответствовать выбранным настройкам и содержать контакт владельца перед публичным запуском.

Лимит SQLite относится к страницам основной БД. WAL и резервные копии требуют дополнительного места. Автоочистка делает страницы повторно используемыми и не гарантирует немедленного уменьшения файла. Настройте оповещения VPS о заполнении диска, памяти, перезапусках и ответах 429/5xx. Не запускайте несколько app-контейнеров на одном socket/volume: квоты и одноразовые токены рассчитаны на один процесс.

## 5. Резервная копия и восстановление

Согласованная онлайн-копия SQLite создаётся штатным backup API, учитывает WAL и проверяется через `quick_check`:

```sh
docker compose run --rm --no-deps backup /backups/manual.sqlite
```

Каждый раз используйте новое имя: существующий backup не перезаписывается. Для выгрузки конкретной копии:

```sh
umask 077
docker compose run --rm --no-deps --entrypoint cat backup /backups/manual.sqlite > ./manual.sqlite
chmod 600 ./manual.sqlite
```

Постоянно работающий app-контейнер не получает backup-volume: копии создаёт отдельный кратковременный контейнер с доступом к рабочей БД только для чтения.

Копия содержит отпечатки, IP, хеш ключа владельца и сессии. Храните её зашифрованной вне VPS, ограничьте доступ и срок хранения. Backup-volume на том же сервере сам по себе не защищает от потери VPS. Регулярный запуск команды можно настроить системным таймером; планировщик автоматически здесь не установлен.

Восстановление выполняйте только при остановленных app и Caddy. Сначала сохраните актуальную копию. Для выбранной копии, уже находящейся в backup-volume:

```sh
docker compose stop caddy app
docker compose run --rm --no-deps maintenance sh -eu -c 'cp /backups/manual.sqlite /data/fingerprints.sqlite; rm -f /data/fingerprints.sqlite-wal /data/fingerprints.sqlite-shm; chmod 600 /data/fingerprints.sqlite'
docker compose run --rm --no-deps maintenance
docker compose up -d
```

Эта операция заменяет текущую базу выбранной копией. Ротация обязательна: она отзывает восстановленные сессии и выдаёт новый ключ. Если переносите локальные записи на VPS, создайте их онлайн-копию тем же скриптом с явным путём назначения, перенесите в backup-volume и используйте этот порядок. Не копируйте только основной SQLite-файл во время работы сервера.

## 6. Обновления

Базовые образы Node 24 LTS и Caddy 2 зафиксированы по registry digest в Dockerfile и Compose. Это делает сборку воспроизводимой. Для обновления сначала проверьте новые официальные версии и их digests, замените значения в этих файлах, затем пересоберите и повторите проверку. Один `pull` не обновляет уже зафиксированный digest. Само приложение не устанавливает npm-пакеты.

```sh
docker compose run --rm --no-deps backup /backups/before-update.sqlite
docker compose pull caddy
docker compose build --pull
docker compose up -d
docker compose ps
```

Смена образов не удаляет volumes. `docker compose down -v` уничтожает базы, ключи, сертификаты и backups — не используйте для обычного обновления.

Ограничения приложения снижают риск перебора и заполнения хранилища. Они не останавливают сетевой DDoS или распределённый поток с тысяч адресов: для такого трафика нужна защита провайдера/edge. Если добавляете CDN, отдельно настройте доверие и очистку IP-заголовков; текущая конфигурация намеренно не доверяет CF-* и клиентскому X-Forwarded-For.

Основания конфигурации: [Caddy HTTPS](https://caddyserver.com/docs/automatic-https), [заголовки reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [ограничение тела](https://caddyserver.com/docs/caddyfile/directives/request_body), [Docker Compose](https://docs.docker.com/reference/compose-file/services/), [Node LTS](https://nodejs.org/en/about/previous-releases).
